# Solid.js 2.0 AI Instructions & API Guide

## Core Principles
1. **Async-first Reactivity**: Computations and `createMemo` can return Promises directly. The reactive graph handles pending/suspension natively.
2. **Boundary Replacement**:
   - Replace `<Suspense>` with `<Loading fallback={<Spinner />}>`.
   - Replace `<ErrorBoundary>` with `<Errored fallback={(err, reset) => <ErrorView error={err} onRetry={reset} />}>`.
3. **Props are read, never destructured**:
   - Incorrect: `function Button({ label, onClick }) { ... }`
   - Correct: `function Button(props) { return <button onClick={props.onClick}>{props.label}</button>; }`
4. **Split `createEffect`**:
   - Takes two functions: compute (tracks dependencies), then apply (runs side effect).
   - `createEffect(() => count(), v => { el.title = v; });`
5. **Draft Stores**:
   - `setStore(draft => { draft.user.name = "New Name"; });`
   - No `produce` wrapper needed.
6. **Optimistic Updates & Actions**:
   - In transition handlers, use `createOptimistic(false, { name: "..." })` and `action(function* () { ... })` to immediately acknowledge the hold before the first `yield`.
7. **Diagnostic Signal Attribution**:
   - Always name reactive primitives: `createSignal(0, { name: "count" })`, `createMemo(fn, { name: "double" })`.
8. **SSR-Safe Context & State**:
   - Never declare module-scope mutable signals or stores. Mount state via Context Providers (`<Context value={...}>` + `useContext(Context)`).
9. **Deterministic Hydration**:
   - Use deterministic seed values during initial server rendering. Generate dynamic client values only inside `onSettled` or actions.
10. **Prop Forwarding**:
    - Use `omitProps(props, "class", "children", "style")` from `~/components/ui/tokens` instead of manual splitting or casting `"style" as any`.
